# CLAUDE.md — проект `luxe/`

Это инструкции для Claude Code. Загружаются автоматически при сессии в `luxe/`.

## Где работаем

- Сессия — только в `luxe/` (TanStack Start, новый сайт MVST).
- Соседние папки в монорепо — **зона коллеги**, не трогать без явной просьбы:
  - `../src/` — легаси Next.js (mvst.ru)
  - `../deploy/` — деплой/докер
  - `../MVST_old/` — архив

## Стек

- TanStack Start + React 19 + TypeScript
- Tailwind 4 + shadcn/ui (Radix)
- Vite 7
- Bun (`bun.lockb` есть; `package-lock.json` оставлен для совместимости)
- Тестов нет — фронт-проверка вручную в дев-сервере

## Данные

- Каталог тянем из TSUM API (`api.tsum.ru/v2`) через `src/lib/tsum/*`.
- Бренд MVST: `MVST_BRAND_ID = 13037770`.
- Типы из API — `src/lib/tsum/types.ts`. Серверные функции — `*.functions.ts`.

## Git workflow

- Интеграционная ветка — `develop` (не `main`). Релизы из `develop` в `main` пойдут позже.
- Репозиторий общий с коллегой. Естественное разделение: я — `luxe/`, коллега — `src/`/`deploy/`. Конфликтов почти не бывает.
- Цикл:
  1. `git fetch && git checkout develop && git pull`
  2. `git checkout -b feature/<topic>` (имя на английском, kebab-case)
  3. Работаю, коммичу
  4. Перед слиянием: `git fetch` → если на `develop` есть свежие коммиты, втянуть их в свою ветку (`git merge origin/develop` или rebase) и разрешить конфликты у себя.
  5. `git checkout develop && git merge --no-ff feature/<topic>` → push
- PR по умолчанию **не делаем** — прямой merge. PR имеет смысл только если ты явно просишь (ревью/CI/обсуждение) или для `develop → main` при релизе.
- Push в `develop` блокируется auto-mode (это shared-ветка). Когда нужно — отдаю команду тебе: ты в чате пишешь `! git push origin develop`, оно выполнится в твоей сессии.

## Коммиты

- Conventional commits со скоупом: `feat(luxe): …`, `fix(luxe): …`, `chore(luxe): …`, `refactor(luxe): …`.
- Заголовок и тело — на русском, кратко, акцент на «зачем», а не «что».
- Один коммит = одна логическая правка.
- Никаких `--no-verify`, `--amend` на уже запушенное, force-push в shared.

## Общение

- Язык: русский.
- Голосовая диктовка — нормально. Вытягиваю суть из потока мысли, не задаю кучу уточняющих по мелочам, принимаю разумные решения и продолжаю.
- Перед рискованным шагом (push в shared, удаление веток/файлов, `reset --hard`, downgrade зависимостей) — спрашиваю.
- Ответы короткие. Без хвостовых саммари «что я сделал». Diff и так видно.

## Код

- shadcn/ui компоненты живут в `src/components/ui/` — переиспользовать, не дублировать.
- Сайтовые компоненты — `src/components/site/`.
- Роуты — `src/routes/` (file-based TanStack Router). Имена с `$` — параметры (`product.$slug.tsx`).
- Утилиты — `src/lib/`. Сшивка классов — `cn()` из `@/lib/utils`.
- Импорты по алиасу `@/…` (см. `tsconfig.json`).
- Комментарии писать только когда «почему» неочевидно (скрытый констрейнт, обход бага, неожиданное поведение). Что код делает — видно из кода. Можно на русском.
- Не плодить абстракции «на будущее». Не добавлять фичи/рефакторы сверх задачи.

## Проверка перед коммитом

- Типы: `npx tsc --noEmit`
- Линт: `npm run lint`
- Дев: `npm run dev` (или `bun run dev`) — `vite dev`
- Build: `npm run build`

- Не пушить ничего в shared-ветки самостоятельно — только локальные операции, push отдаю тебе.
- Не делать «заодно» рефакторинг несвязанных файлов.
